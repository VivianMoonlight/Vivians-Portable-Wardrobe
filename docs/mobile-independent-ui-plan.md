# Mobile 独立 UI 改造方案（衣柜 / 历史记录 / 设置）

## 1. 目标与范围

基于你的 5 点需求，本方案将当前“`Studio` 移动收缩版”改为“手机端独立 UI”，并明确：

- 仅保留 3 个一级入口：`衣柜`、`历史记录`、`设置`。
- 在 `衣柜` 和 `历史记录` 两个入口下，主可视区以中间“衣橱管理”窗口为核心。
- 在 `衣柜` 和 `历史记录` 中提供底部功能栏 + 左右滑动切换三窗口（预览 / 衣橱 / Filter）。
- 三个功能区统一触屏优先交互（点击、滑动、长按、底部操作区）。
- 手机端 UI 全屏占据浏览器可用区域（含安全区）。

不在本次范围：

- 桌面端 `Studio` 的交互改造。
- 增加额外业务面板（例如更多 tab 或复杂浮窗）。

---

## 2. 现状分析（与你当前实现的差距）

当前 `src/components/Studio/Studio.vue` 的移动逻辑是：

- 仍以 `Studio` 结构为主，通过 `isMobile` + `mobileTab` 做折叠。
- 移动 tab 仍包含 `structure / replace / property / history`，与目标的 `衣柜 / 历史记录 / 设置` 不一致。
- 结构上仍是“桌面工作台缩小版”，而非手机独立壳层。
- 没有形成“底部功能栏 + 手势切换三窗口”的统一机制。

结论：

- 需要“新增手机壳层”而不是继续在 `Studio.vue` 上堆条件分支。
- `Studio.vue` 在手机端应降级为复用内容组件来源，而非继续承担页面骨架。

---

## 3. 信息架构（IA）与交互模型

## 3.1 一级导航（手机独立）

仅三个主 tab：

1. 衣柜
2. 历史记录
3. 设置

建议采用底部主导航（固定在安全区内）。

## 3.2 二级工作区（仅衣柜/历史记录）

在 `衣柜` 与 `历史记录` 下，内容区统一为三窗口横向分页：

- 页 1：预览（Preview）
- 页 2：衣橱（Wardrobe，主窗口，默认页）
- 页 3：Filter

切换方式：

- 左右滑动（主方式）
- 底部功能栏点击切换（辅方式）

默认落点：

- 进入 `衣柜` 或 `历史记录` 时，默认定位到中间页（衣橱）。

## 3.3 设置页

设置页不承载三窗口，仅显示设置列表/分组，保持全屏滚动。

---

## 4. 布局与全屏规范

手机端根容器统一规则：

- 高度：`100dvh`（必要时加 `--dvh-safe` 兜底）。
- 宽度：`100vw`。
- 安全区：底部和顶部使用 `env(safe-area-inset-*)`。
- 页面滚动职责：
  - 根容器不滚动（除设置页内容区）。
  - 三窗口内部各自管理滚动。

推荐结构（抽象）：

- 顶部：标题/上下文状态（可简化）。
- 中部：三窗口横向 pager（衣柜/历史记录页使用）。
- 底部：
  - 二级功能栏（预览/衣橱/Filter）
  - 一级主导航（衣柜/历史记录/设置）

---

## 5. 触屏交互规范（适配需求 4）

三个功能区统一触屏策略：

1. 点击：主操作按钮命中区不小于 44px。
2. 滑动：横向滑动切页，避免与纵向滚动冲突。
3. 长按：用于次级操作（如批量/上下文菜单），替代右键语义。
4. 底部操作：高频动作收敛到底部功能栏，减少顶部触达成本。
5. 状态反馈：切页时提供明确 active 指示（文本+图标其一即可）。

冲突处理建议：

- 当子区正在纵向滚动时，禁用横向切页手势抢占。
- 横向滑动需设置最小位移阈值，避免误触。

## 6. 对现有实现的修改建议（按文件）

## 6.1 新增手机壳层组件（推荐）

新增：`src/components/mobile/MobileWardrobeShell.vue`

职责：

- 手机端一级导航（衣柜/历史记录/设置）。
- 衣柜/历史记录下的三窗口 pager 与底部功能栏。
- 全屏布局与安全区处理。

原因：

- 可避免在 `Studio.vue` 中继续堆叠 `isMobile` 分支。
- 将“桌面工作台”与“手机独立 UI”彻底分层。

## 6.2 复用现有子组件而非重写业务

可复用候选：

- 预览：`PreviewWidget.vue`
- 衣橱管理主区：`PartListPanel.vue`（必要时加移动模式 prop）
- Filter：`AssetSelectorPanel.vue` / `PalettePanel.vue`（按业务选择其一或组合）
- 历史：`HistoryPanel.vue`

建议给上述组件补充轻量 prop：

- `mobileMode: boolean`
- `touchOptimized: boolean`

用于切换触屏样式和交互细节，不改变业务数据源。

## 6.3 调整 `Studio.vue` 的手机职责

文件：`src/components/Studio/Studio.vue`

建议：

- 手机端不再渲染当前 `mobile-tabs` 结构。
- 在入口层判断手机时直接挂载 `MobileWardrobeShell`。
- `Studio.vue` 保持桌面工作台职责，减少移动分支。

## 6.4 Store 层状态拆分建议

文件：`src/stores/studioStore`（或现有等价 store）

新增（或归并）状态：

- `mobileMainTab: 'wardrobe' | 'history' | 'settings'`
- `mobileSubPane: 'preview' | 'wardrobe' | 'filter'`
- 可选：`mobileHistorySubPane`（若历史页需要独立记忆）

持久化：

- 仅持久化一级 tab（可选二级），避免每次进入重置。

## 7. 实施方案（分阶段）

## Phase 1：搭建手机独立骨架（0.5~1 天）

交付：

- 新建 `MobileWardrobeShell.vue`。
- 完成全屏 + 安全区 + 一级三 tab。
- 设置页先占位（可复用现有设置块）。

验收：

- 手机端进入后不再看到 `Studio` 旧 mobile-tabs。
- UI 覆盖全屏，无桌面布局残留。

## Phase 2：接入衣柜/历史记录三窗口 pager（1 天）

交付：

- 衣柜与历史记录页均接入 `Preview / Wardrobe / Filter` 三窗口。
- 默认中间页（Wardrobe）可见。
- 底部功能栏切换 + 滑动切换可用。

验收：

- 两个 tab 的三窗口均可稳定切换。
- 中间窗口视觉上占主导（默认焦点与占比）。

## Phase 3：触屏优化与冲突治理（0.5~1 天）

交付：

- 提升触控命中区（44px+）。
- 处理横滑与纵滚冲突。
- 长按次级操作（如需要）。

验收：

- 误触率可控，滑动切页顺畅。
- 列表滚动时不会被错误切页。

## Phase 4：回归与文档更新（0.5 天）

交付：

- 回归衣柜、历史、设置三主链路。
- 更新 `docs` 中相关移动端计划索引。

## 8. 验收清单（严格对齐你的 5 点）

1. 不考虑 `Studio`：
   - [ ] 手机端仅有衣柜/历史记录/设置三个一级入口。

2. 中间窗口占主界面、竖屏适配：
   - [ ] 衣柜/历史记录默认显示中间“衣橱管理”窗口。
   - [ ] 竖屏下布局无横向溢出。

3. 底部功能栏 + 左右滑动切换三窗口：
   - [ ] 预览/衣橱/Filter 可通过底栏点击切换。
   - [ ] 同时支持左滑/右滑切换。

4. 三功能区触屏优化：
   - [ ] 关键点击位 ≥ 44px。
   - [ ] 滑动与滚动冲突已处理。

5. 浏览器全屏：
   - [ ] 手机端主容器占据 `100dvh`，安全区显示正常。

## 9. 风险与规避

1. 风险：与现有 `Studio` 移动逻辑并存造成双入口。
   - 规避：手机端入口统一收敛到 `MobileWardrobeShell`，旧逻辑仅保留桌面。

2. 风险：横滑与内部列表纵滚冲突。
   - 规避：引入手势阈值 + 方向锁（先判定主方向再抢占）。

3. 风险：组件复用导致样式耦合。
   - 规避：通过 `mobileMode/touchOptimized` prop 做样式分支，不改业务核心。

---

## 10. 推荐决策（简版）

推荐采用“新增手机壳层组件 + 复用业务子组件 + store 增加移动导航状态”的方案。该方案对现有架构侵入最小，且能最快满足你提出的 5 条需求，并为后续手机端单独迭代保留清晰边界。
