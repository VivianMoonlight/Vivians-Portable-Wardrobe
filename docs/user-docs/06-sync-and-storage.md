# 云同步与容量

衣橱会先把修改保存到本机，再尝试同步到 BC 账号。衣橱容量区可以分别查看本机保存结果、云端进度和共享容量，并可“重试上传”；展开详情可查看剩余空间及可用的迁移备份导出。

## 先看同步状态

| 界面提示 | 表示什么 |
| --- | --- |
| 已保存到本机 | 当前修改已写入这个浏览器的本地存储 |
| 本机已保存 | 云端状态尚无可用的提交结果；可能未提交，也可能重开后暂缺可信登录基线 |
| 已提交（默认成功） | 已调用 BC 提交接口，默认视为同步成功；本机仍保留后续冲突比对记录 |
| 已与云端核对 | 下次完整登录回读的数据与待同步内容相符 |
| 离线、容量超限或同步需要处理 | 上传未完成，按提示恢复连接、减少同步内容或重试 |

BC 的 `AccountUpdate` 没有逐次成功回执，因此不会出现每次上传后自动消失的“等待核验”。提交调用成功后，界面默认视为同步成功；下次完整登录回读用于检查差异或冲突，不是逐次写入确认。点击“重试上传”可重新尝试提交，不会主动读取云端。换设备前仍建议保留 JSON 备份，并在新设备确认衣物可用。

如果只读到游戏中的旧缓存、尚未取得新鲜云端快照，且本机内容与该缓存相同，点击“重试上传”不会重传这份可能过时的内容；下次完整登录后再用新鲜回读数据比对。普通断线自动重连不一定重新加载扩展设置。

## 选择哪些衣物参与同步

在衣物卡牌或列表中点击“参与云同步”或“仅保存在本机”，即可切换这件衣物的同步开关。

- **关闭**：保留本机衣物，后续上传不再包含其衣物内容。其他设备已经保存的本机副本不会自动擦除。
- **重新开启**：从仍保留衣物的设备点击开关，将这件衣物重新加入同步。
- **删除衣物**：与关闭同步不同，会记录删除，并在副本交换数据时传播。

衣物开关独立于标签；改标签不会自动改变同步范围。标签名称及少量同步元数据仍会上传，因此“仅保存在本机”不表示其所有关联标签都隐藏于云端。

## 为什么出现“保留的本机副本”

如果你在本机修改了一件已关闭云同步的衣物，而另一台设备重新开启了这件衣物的同步，两边可能存在不同版本。收到对方的版本后，衣橱会保留重新开启同步的版本，并将本机改过的内容另存为一件独立衣物，在卡牌和列表中标记“保留的本机副本”。

此副本默认仅保存在本机，不会因另一台设备开启同步而自动上传。可以分别预览两个版本，再决定保留哪些内容；需要同步这个副本时，手动开启它的云同步。开启后，它会作为独立衣物参与同步，不再显示本机副本标记。名称相同不代表它们是同一件衣物。

## 多台设备同时修改的限制

VPW 会合并它已收到的副本，但 BC 对衣橱使用同一个云端字段，上传时替换整份内容，没有服务端版本检查来拒绝过时的写入。因此，另一台设备仍可能用旧内容覆盖较新的云端内容；删除记录和本机副本保护不能消除这个覆盖窗口。

“已与云端核对”只表示收到的新云端数据曾与本次待同步内容一致，不保证之后不会被另一台设备覆盖。多设备操作时，尽量先结束一台设备的编辑，再在另一台登录并查看数据。重要修改后保留独立 JSON 备份，确认新设备内容完整后再清理原设备的数据。

## 容量为什么会满

面板按 **180000 字节（180 kB）**检查整个扩展设置，并另行检查上传单包大小。这是所有扩展共享的预算，VPW 能用的空间会受到其他扩展影响。

面板列出 **VPW、其他扩展、总用量、剩余量**，均按 1000 字节换算为 1 kB。用量达到 80% 时提示接近上限；超限时暂停上传，不删除已经保存的本机衣物。

可以把不常用或体积较大的衣物设为“仅保存在本机”，然后重试。删除标签不能保证明显释放空间；为防止旧设备恢复已删内容，系统还要保留删除记录。

这里的容量数字只针对 BC 云端 `ExtensionSettings`。如果出现 `VPWardrobe_index_*` 的 `QuotaExceededError`，失败的是向此站点的浏览器 `localStorage` 写入。即使磁盘空间充足，站点独立配额或浏览器存储策略也可能拒绝写入；云端显示 VPW 0.0 kB、其他扩展 0.0 kB，不能据此判断本机空间。报错区域另行估算此站点 `localStorage` 已存的 VPW、其他数据及合计用量，不包含被拒绝的写入，也不是剩余可用容量。请按下方“备份与换设备”的步骤保护现有数据，然后点击“重试本机保存”。

## 用标签整理衣橱

1. 点击“管理标签 → 新建标签”，输入全局不重复的名称。
2. 打开衣物的“更多操作 → 编辑标签”，选择一个或多个标签，再点“保存标签”。
3. 在桌面旁侧筛选列表，或手机“筛选”抽屉里选择“全部衣物”“未加标签”或某个标签；搜索框同时搜索衣物名和标签名。
4. 要改名或删除标签，先在筛选列表选中它，再使用“管理标签”。删除标签不会删除衣物。

旧文件夹首次升级后会变成完整路径标签。例如 `日常 / 夏季`，其中的衣物同时带有 `日常` 和 `日常 / 夏季`。这只是标签名称，不需要逐层进入文件夹。

## 备份与换设备

衣橱索引使用浏览器的 `localStorage`，空间有限；历史记录只保存在本机 `IndexedDB`，不上传 BC。清理站点数据、换浏览器或换设备都会影响这些本机数据。新版优先用 UTF-16 压缩本机衣橱索引，浏览器拒绝该写入时回退 Base64；仍可读取旧版 Base64 索引，并在条件允许时压缩旧数据。BC 云端格式不变。压缩可以减少部分本机占用，但不能保证浏览器一定接受写入。旧版历史记录确认写入 `IndexedDB` 后才移除原 `localStorage` 项；如果两份历史不一致，旧副本会另存到 `IndexedDB`，确认写入后再移除原项。历史页的“导出历史”包含当前记录及归档的旧副本。

旧版 React 脚本无法读取新版写入的 UTF-16 本机索引，也不会读取新版的 `IndexedDB` 历史。降级前先用新版导出并核对衣橱 JSON 备份，再确认旧版支持的导入格式；衣橱 JSON 备份不包含历史记录。这次没有改动云端数据格式。

本地保存失败时，先从“导入 / 导出 → 保存备份”导出当前仍可读取的 JSON，并打开文件核对衣物内容。之后查看报错区域的此站点用量估算，仅处理确认不需要的同站点数据，回到衣橱点击“重试本机保存”。不要直接清除整个站点数据；清理其他网站的数据通常不能解决此站点的独立配额。如果备份不能导出或内容无法核对，先不要清理。未成功保存的修改也不能依赖这份备份恢复。

- 在“导入 / 导出 → 保存备份”导出当前衣橱 JSON，包含本机衣物和标签。
- 升级时有旧数据归档，容量区会出现“导出迁移前备份”。请保存这份恢复材料，原始旧数据不会自动重新并入新衣橱。
- “导入 / 导出 → 备份导入”会把备份中的衣物作为新副本加入，并复用同名标签；重复导入可能产生重复衣物。

换设备前保存一份 JSON 备份，在新设备确认衣物可用后再处理旧设备。云同步方便跨设备使用，独立备份方便恢复误删和未同步内容。

技术细节和协议边界见 [衣橱索引与云同步](../INDEXED_WARDROBE_SYNC.md)。
