# 故障排查与 FAQ

先记录界面提示，再处理对应问题。涉及数据时，优先使用“导入 / 导出 → 保存备份”保存当前可读衣橱，保留旧备份原件。

## 列表里找不到服装或标签

- 选择“全部服装”，清空搜索；“未加标签”只显示没有有效标签的服装。
- 检查当前登录账号。衣橱本地数据按账号隔离，不会混用其他账号的数据。
- 旧目录已转换成完整路径标签，例如 `日常 / 夏季`；当前版使用标签筛选，不提供目录导航或拖拽归档。
- 删除标签不删除服装，可回到“全部服装”查找。标签名称经规范化和去首尾空白后不能重名。

## 预览或应用没有达到预期

1. 点击服装卡片进入“预览与微调”；悬停不切换预览，双击也不会直接应用。
2. 每次选衣先完整使用所选衣物。需要保留原外观时，使用“保留原身形”、组来源或单部件滑块调整。
3. 查看目标角色和部件来源；组来源按补入、覆盖、完全替换循环，单部件直接选择原角色、所选衣物或置空。
4. 套装缺少某个部位、资产不可用、锁具或游戏权限限制，都可能影响结果。预览组合规则不保证实际换装一定成功。

组完全替换后，来源没有某部件时实际结果可以为空，滑块仍显示该来源；这不表示它自动切到了手动“置空”。确认预览后，通过末尾的“应用到「角色名」”完成换装。

## 误换了外观

打开“历史”，点击相关记录查看预览，再通过记录菜单“应用”或双击尝试恢复。请根据内容选择记录，不要固定假设倒数第二条就是所需状态。

历史容量有限，应用也受当前权限和资产可用性限制。已满意的外观应另存到衣柜，历史记录不是长期备份。

## BCX 或 JSON 导入失败

- BCX 代码应是完整的 Base64 + LZString 压缩内容，粘贴到“导入 / 导出 → 从 BCX 导入”。
- JSON 文件使用“导入 / 导出 → 备份导入”；此入口不读取 ZIP。
- 检查是否把迁移恢复归档当成普通备份导入。恢复归档须先提取其中的旧衣橱对象。
- 保留报错文本和原始文件；不要删除未知字段或反复导入来碰运气。重复成功导入会新增副本。

具体格式见 [数据与备份](05-data-backup-import-export.md)。若 BCX 导出提示后剪贴板仍为空，检查浏览器剪贴板权限并重新导出、粘贴核对。

## 容量超限，上传暂停

面板按 180000 字节（180 kB）检查所有扩展共享的设置预算，并另行检查上传单包；其他扩展也占空间。

把较大的、不常用的服装卡片设为“仅保存在本机”，观察 VPW、其他扩展、总用量和剩余量，再点“重试上传”。超限不会删除已经成功保存的本机服装；标签与删除记录仍占少量同步空间。

容量条回到限额以内，只说明允许尝试上传，不表示云端已确认保存。

## 换电脑后没有新服装

1. 回到原设备，检查这些服装是否“参与云同步”，以及是否“已保存到本机”。
2. 查看云端状态是否仍为离线、等待上传、容量超限或错误；恢复连接、处理提示后点击“重试上传”。
3. “已提交，等待核验”没有服务端保存确认。登录或重连返回的新数据相符后，才显示“云端回读已核验”。
4. 若仍不同步，使用原设备导出的 JSON 在新设备显式导入；确认新设备服装可用后再清理旧设备。

更多边界见 [云同步与容量](06-sync-and-storage.md)。避免让新旧版本同时编辑同一个账号；新索引出现后，旧云目录只归档，不自动重新并入。

## 提示尚未保存到本机或本地存储失败

本地存储并非无限；浏览器配额、隐私设置、禁用站点存储或清理站点数据都可能影响写入。先导出当前可读衣橱和迁移恢复材料，处理具体错误后重新打开衣柜。

不要把清理站点数据当作云端衣橱重置操作：它会移除本机记录，不能替代同步删除。

## 常见问题

**导入玩家衣柜会改写原版衣柜吗？**

此操作只读取原版非空服装槽，向 VPW 新增服装及标签。之后在 VPW 整理标签不会改写原版槽位。

**如何清空衣橱？**

当前界面没有根文件夹或一键清空衣橱入口。先导出备份，再通过各服装的“更多操作 → 删除”处理；删除标签只取消分类。

**删除的服装会被旧设备带回来吗？**

新索引的删除记录会阻止同一 ID 被旧副本复活；主动导入备份会创建新 ID 的副本。设备需要交换状态才能传播删除，云端整块写入仍有并发竞争边界。

**能绕过锁具或给无权限的角色强制换装吗？**

不能。服装应用需要通过当前游戏环境的目标及权限检查，槽位规则不会授予额外权限。
