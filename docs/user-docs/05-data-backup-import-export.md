# 数据与备份

当前版支持衣橱 JSON 备份、单套 BCX 代码和原版玩家衣柜导入。备份中的服装作为新副本加入，不覆盖现有衣橱。

## 导出与导入衣橱 JSON

1. 打开衣橱，选择“导入 / 导出 → 保存备份”。
2. 保存浏览器下载的 `vpw-backup_时间戳.json`；文件包含当前服装、标签和同步元数据，也包含仅保存在本机的服装。
3. 到目标浏览器选择“导入 / 导出 → 备份导入”，选中该 JSON 文件。
4. 查看新增数量、本机保存结果及云端状态；导入成功不等于云端已核验。

导入会为服装创建新 ID，并复用全局同名标签。备份内的服装标签和单件云开关会保留；如当前选中具体标签，也会加上该标签。重复导入同一备份可能生成重复服装。

常规衣橱备份不包含历史记录或全部界面偏好。删除后从备份恢复会得到新副本，不会撤销旧 ID 的删除记录。

## 支持哪些输入

“备份导入”读取合法 JSON，当前支持：

- 新版衣橱索引。
- 旧版文件夹树，以及包含 `fs` 字段的旧备份；目录会转换成完整路径标签。
- 含 `data` 部件数组的单套服装对象，或直接保存的部件数组；部件数组会先提示输入服装名称。

这不是任意服装软件的通用导入器，也不支持直接读取 ZIP 压缩包。保留原文件；遇到无法识别格式时不要把它改成空数组再尝试。

## 单套 BCX 分享

1. 在服装“更多操作”或桌面右键菜单选择“导出为 BCX”。
2. 系统会尝试把代码复制到剪贴板；先粘贴到纯文本区域确认代码完整，再分享。
3. 接收方打开“导入 / 导出 → 从 BCX 导入”，粘贴完整代码并确认。
4. 如果导入的是部件数组，输入服装名称；如已选中具体标签，新服装会获得该标签。

BCX 输入使用 Base64 + LZString 压缩 JSON。单套导出只包含装扮部件，不携带这套服装的名称、标签或整个衣橱。

## 从原版玩家衣柜导入

选择“导入 / 导出 → 导入玩家衣柜”。系统读取原版衣柜中的非空服装槽，创建带时间戳的 `Player_Wardrobe_…` 标签，并把新服装归入该标签。

该操作读取原版衣柜，向 VPW 新增副本；整理 VPW 标签不会改写原版衣柜。再次执行会再导入一批副本。

## 迁移前恢复材料

升级时若发现旧数据，展开衣橱容量区的详情可“导出迁移前备份”，下载 `vpw-recovery_时间戳.json`。它保留来源、原始值和旧衣橱内容，方便核对迁移或排查问题。

这份文件是恢复归档，不是普通衣橱备份，不能直接按部件数组导入。需要恢复其中的数据时，应先提取归档内的旧衣橱对象（例如 `data.local[].value` 或 `data.online`），另存为 JSON 后再使用“备份导入”；不确定时保留原文件再排查。

## 换设备前

先保存独立 JSON 备份，再确认需要的服装开启了“参与云同步”。“已提交（默认成功）”表示已调用 BC 提交接口，并非收到了逐次回执；到新设备确认数据可用后，再处理旧设备。

本地存储容量有限，清理站点数据会删除本机副本。容量和重试说明见 [云同步与容量](06-sync-and-storage.md)，导入异常见 [故障排查](08-troubleshooting-faq.md)。
