# StackList UI/UX 重构与功能增强方案（执行版）

> 目标组件：`src/components/Studio/StackList.vue`  
> 目标：在不改变核心业务语义（Stack 增删改选、复制、拖拽重排）的前提下，提升信息密度、可达性、操作效率与可维护性。  
> 时间：2026-02-23

## 1. 现状诊断（问题清单）

### 1.1 视觉与信息层级
- 工具区仅有图形字符按钮（`＋`, `⧉`, `✎`, `✖`），语义识别成本高。
- 列表缺少全局信息反馈（总数、已选状态、当前可视结果数）。
- 空状态仅提示“为空”，没有针对“搜索无结果”的反馈。

### 1.2 交互效率
- 无搜索/过滤能力，Stack 数量上升后定位效率急剧下降。
- 仅支持拖拽重排，缺少键盘可达的顺序调整能力。
- 行内重命名输入框 focus 逻辑依赖 `ref` 数组访问，存在不稳定风险。

### 1.3 可访问性与一致性
- 行项是可点击容器但缺少完整键盘语义（`Enter/Space` 选择）。
- 操作按钮未统一遵循当前设计体系组件（`BaseButton`）。
- 缺少明确的 `aria-*` 描述（如“当前激活项”“上下移动”等）。

### 1.4 数据与状态安全
- 重命名逻辑直接写 `store.stacks = copy` / fallback 直接改引用，历史快照行为不稳定。
- 过滤与重排、删除状态（armed）之间缺少更严格的状态清理策略。

---

## 2. 设计目标（North Star）

1. **一眼可读**：列表头部展示总量、当前可见量、当前选中名称。
2. **两步到达**：支持输入搜索词后直接定位目标 Stack。
3. **可键可鼠**：鼠标拖拽 + 键盘选择/重排（行焦点 + 上下移动按钮）。
4. **一致可信**：操作按钮、状态色、焦点反馈统一使用现有主题 token。
5. **可回退**：重命名与顺序调整触发历史快照，确保 Undo/Redo 可用。

---

## 3. 交互重构方案

## 3.1 顶部工具区（Header）
- 左侧：标题 + 二级信息（`N stacks` / `M visible`）。
- 中间：搜索输入（名称匹配，实时过滤）。
- 右侧：主操作（新建、完整复制、按过滤复制）。

### 搜索行为
- 仅按 `stack.name` 进行大小写不敏感匹配。
- 空关键字显示全部。
- 有关键字但无命中：显示“无匹配结果”空态。

## 3.2 列表项（Row）
- 保留“倒序展示”规则（最新在上，store index 映射不变）。
- 左区：拖拽手柄 + 名称/元信息。
- 右区：操作按钮（上移、下移、重命名、删除）。
- 激活项强化：边框、阴影、左侧强调条。

### 快捷重排（新增）
- 提供行内“上移/下移”按钮（内部映射到 `store.moveElement`）。
- 对首项/末项自动禁用对应方向按钮。

## 3.3 重命名体验
- 行内编辑，`Enter` 提交，`Esc` 取消，`blur` 提交。
- 提交时 trim；空字符串不写入。
- 成功写入后调用 `refreshMergedAppearanceData` 与 `pushHistorySnapshot`。

## 3.4 删除确认
- 保留“arm-confirm”双击语义。
- armed 状态的视觉提示提升（danger token + 轻高亮）。
- 外部点击时清空 armed，并自动结束重命名。

## 3.5 键盘可访问性（新增）
- 行可 focus（`tabindex=0`），支持 `Enter/Space` 选择。
- 列表区域声明 `role=list`，行声明 `role=listitem` 与 `aria-selected`。
- 所有 icon-only 操作补齐 `aria-label`。

## 5. 技术落地策略

- 文件改动：
  - `src/components/Studio/StackList.vue`
  - `locales/zh.json`
  - `locales/en.json`
- 不修改 Store 的核心 API，仅复用：
  - `addElement` / `removeElement` / `moveElement` / `select`
  - `refreshMergedAppearanceData` / `pushHistorySnapshot`
- 视觉 token：复用既有 `--color-*`、`--radius-*`、`--space-*`、`--shadow-*`。

## 6. 验收标准（DoD）

1. Stack 列表支持实时搜索，过滤行为正确。
2. 新建、复制、删除、重命名、拖拽重排全部可用。
3. 上移/下移按钮可正确改变顺序且禁用态正确。
4. 选择、重命名、删除具备键盘可达性。
5. 构建通过（至少 `npm run build` 无新增错误）。
6. i18n key 在 `zh/en` 均存在，无回退到硬编码文本。

---

## 7. 备注

本方案优先“效率 + 一致性 + 可维护性”，避免引入重型交互（如多列虚拟化、复杂排序器）导致认知负担上升；在后续迭代可考虑加入：批量选择、收藏/最近访问、命令式快速跳转。
