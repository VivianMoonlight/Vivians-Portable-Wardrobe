# 衣橱索引与云同步

React 衣橱使用按账号隔离的索引：服装独立存放，以多个标签组织；先保存本机，再同步到 BC 的 `Player.ExtensionSettings.VPWardrobe`。

## 数据与合并规则

- `schemaVersion: 3`，包含 `outfits`、`tags`、`tombstones`、`cloudState` 与逻辑时钟 `clock`。
- 服装具有稳定 ID；改名、调整标签或云同步开关不会换 ID。同名服装可以并存。
- 一件服装的 `tagIds` 可以关联多个标签。标签名称经 NFKC 规范化和首尾空白清理后全局唯一；创建、改名时拒绝重名。
- 两台设备并发创建的同名标签，在界面合并为一项并保留 ID 别名，既有服装关联仍有效。删除该标签会处理其全部别名。
- 每条记录按 `[逻辑计数器, 副本 ID]` 排序；相同修订的异常数据也采用确定性选择。物理时间只用于状态展示，不决定冲突胜负。
- 合并以实体 ID 为单位。同一服装的并发编辑选择一个完整记录，不能承诺逐字段保留两边修改；不同 ID 的记录可以汇合。
- 删除服装或标签写入永久墓碑，旧副本不能复活同一 ID。删除标签不删除服装；云端缺少某条记录也不等于删除。
- 墓碑不自动过期，因为无法证明全部离线副本都已见过删除。它们会持续占用容量。

## 云同步开关

`cloudState[id]` 单独保存开关及修订。编辑旧服装内容不会顺带重新开启云同步；明确关闭后，可在持有本机副本的设备重新开启。

关闭后，本机服装仍可使用，下一次云端投影不包含其服装内容。开关元数据、标签和墓碑仍参与同步。已在其他设备落地的本机副本不会被远程擦除；没有本机副本的设备不会因旧云端内容而重新获得已关闭同步的服装。

若别的设备重新开启同一衣物的同步，本机在关闭期间的私有修改会保留为独立的仅本机副本，原 ID 采用明确发布的版本。卡牌和列表会标明该副本；只有用户手动开启它的云同步才会发布其内容。删除副本后，其来源 ID/修订墓碑元数据目前可能仍进入云端投影，但衣物名称和内容不会上传。

## 一次性旧目录迁移

1. 本地唯一主记录键为 `VPWardrobe_index_<MemberNumber>`，保存压缩后的索引、待同步状态和恢复备份索引。
2. 已有有效新索引时，以新索引为基础合并。云端已有新索引时，旧目录只作为恢复材料。
3. 首次迁移旧本地数据时，依次优先读取旧 React 键 `VPWardrobe_VPWardrobe_local_<MemberNumber>`、旧 main 键 `VPWardrobe_<MemberNumber>`、更早的 `VPWardrobe<MemberNumber>`；没有旧本地来源才从旧云目录迁移。
4. 迁移前归档旧来源，使用 `raw`、`onlineRaw` 保留本地及云端原始存储值，同时保留原键。界面可“导出迁移前备份”；存储错误或不可识别数据会显示错误，不当作空衣橱覆盖。
5. 每个旧目录变成完整路径标签，例如 `日常 / 夏季`；服装同时获得各级祖先标签。相同路径冲突增加稳定后缀，旧 ID、删除记录和继承的云开关尽量保留。
6. 新索引建立后，后来出现的旧云目录只归档，不自动重新导入，避免旧客户端带回已删除内容。需要恢复时显式导入备份，作为新 ID 的副本加入衣橱。

恢复导出是包含旧来源的归档材料；日常“保存备份”导出当前索引。备份导入会新增副本并复用同名标签，不覆盖整个衣橱，也不是把旧墓碑撤销。

## 持久化与状态

本地 `localStorage` 写入成功后，才将操作显示为已保存。本地配额耗尽或写入失败会报告错误；浏览器空间有限，清理站点数据也会删除本机记录。

待同步状态随账号索引落盘。提交前读取并合并同源其他标签页的本地索引；`storage` 事件触发后续合并。相同内容避免反复提交，传输异常采用有界退避重试；离线和超限时暂停，恢复连接、后续修改或手动重试可以继续处理。

| 状态 | 含义 |
| --- | --- |
| `pending` | 本机已保存，尚未得到新鲜云端快照核对 |
| `submitted` | 已调用游戏提交接口，等待云端回读核验 |
| `verified` | 收到新鲜云端快照，合并后的云投影与之相符 |
| `offline` / `quota` / `error` | 分别为离线、容量阻止或需要处理的错误 |

BC 写入接口没有逐次服务端确认或 CAS。修改 `Player.ExtensionSettings` 的本机缓存不能证明云端成功。首次打开不把缓存标为已核对，也不会在缓存与本机投影相同时重传；登录、重连时使用 `LoginResponse` 返回的新鲜数据核对。本会话新编辑仍可提交，单字段并发覆盖尚无法由客户端消除。

此方案以最终一致性为目标：同源 `localStorage` 的读改写也不是事务，云端整块覆盖仍有竞争窗口。只有副本再次交换状态，才能合并各自保留的修改；不能承诺跨设备强一致性或任意并发下绝对无损。“重试上传”只重新提交，不提供主动云端读取或服务端确认。

## 容量计算

VPW 对整个拟写入的 `Player.ExtensionSettings` 执行 **180000 字节**共享预算：替换 VPW 值后，将完整 JSON 按 UTF-8 计数，并另行计算实际 `AccountUpdate` 单包（含协议前缀）。任一超限就停止上传，保留已成功保存的本地数据。

面板显示 VPW、其他扩展、总用量和剩余量，使用十进制 `kB`（1000 字节）。VPW 用量是替换后的共享 JSON 增量，包含键名、引号和分隔符；标签、墓碑等同步元数据也计入。80% 起提示接近上限。

上游 [BC 服务端 app.js](https://github.com/Ben987/Bondage-Club-Server/blob/9cfaaeffab8b417df9db7fcb0d1e3b9092b6c922/app.js#L37) 配置的是 Socket.IO `maxHttpBufferSize: 180000`。这是单包限制；本项目将相同数值用于共享设置预算，是客户端容量策略，不能称为服务端专门给 VPW 分配的空间。

## 设计依据与验证范围

采用 [Microsoft `system-type-distributed` skill](https://github.com/microsoft/amplifier-bundle-systems-design/blob/1eff6a2bcebe7c42d5d8d4962e1937a3bb932b0c/skills/system-type-distributed/SKILL.md) 的副本合并、幂等重试、故障恢复和确认语义；没有引入额外云服务。

回归检查应覆盖：多副本删除与合并、同名标签、关闭再开启、旧目录迁移、原始恢复备份、本地写入失败、共享配额与单包边界、重复提交、离线重连及登录核验。

- `npm test`：运行索引、迁移、持久化及相关单元测试。
- `npm run test:browser`：按 [playwright.config.js](../playwright.config.js) 启动或复用 `127.0.0.1:5180` 的模拟宿主，检查标签操作、刷新后持久化、配额提示及移动布局；Windows 默认 Edge，其他平台默认 Chromium，可通过 `PLAYWRIGHT_CHANNEL` 指定通道。
- `npm run typecheck`、`npm run build`：检查类型与生产构建。

模拟宿主的浏览器测试不能代替真实账号在两台设备上的云端回读验证。
