# 索引衣橱与换装流程

React 预览版发布到 `wardrobe-react`。运行 `npm run dev` 后访问 `/`，点击衣橱入口即可使用正式 React 组件。开发宿主为模拟环境；真实 BC 的资源、权限与扩展交互需要在游戏中确认。

## 浏览、预览与应用

衣物通过稳定 ID 建立索引，每件可引用多个名称全局唯一的标签。旧文件夹按完整路径迁移为标签，迁移备份与云端冲突规则见 [索引与同步](INDEXED_WARDROBE_SYNC.md)。

浏览区提供两种视图：**卡牌**用 CSS columns 排成瀑布流，人物画幅保持 9:16；**列表**只展示名称、标签和操作，不创建缩略图。桌面筛选栏列出全部衣物、未加标签、标签计数及云同步范围；窄屏使用筛选抽屉。搜索同时匹配衣物和标签名称。

点击或键盘选择衣物时，捕获目标角色当前外观作为原角色基准，将全部部位切到所选衣物，默认完全替换。桌面在右侧打开试穿预览与应用栏，浏览区继续可用；手机切换到独立预览页面。桌面收起预览、手机点击「返回衣橱」，都会保留搜索、筛选和浏览位置。再次选衣重新开始完全替换。

点击「微调部位」时，桌面打开弹窗，手机切换到独立微调页面；预览随调整实时更新。「完成微调」返回预览并保留调整，手机的「返回预览」和桌面弹窗的关闭按钮也保留调整。最终通过预览中的「应用到『角色名』」换装；游戏权限和锁定限制仍由 BC 适配器检查。

## 按当前内容决定分组操作

每个部件只记录 `original`、`incoming` 或 `empty`，单个滑块直接选择来源。分组的来源按钮根据**当前预览内容**显示下一步操作：

| 当前预览相对于所选来源 | 下一步 | 改动范围 |
| --- | --- | --- |
| 来源提供的部位仍有空位 | 补入 | 只填空位，保留已有部件 |
| 来源提供的部位都有内容，但内容不同 | 覆盖 | 替换来源提供的部位，其余选择保留 |
| 来源提供的部位已一致 | 完全替换 | 整组切到该来源，同时清空来源没有的部位 |
| 整组来源与内容都已完全替换 | 已完全替换 | 按钮禁用，保留结果 |

「原角色」和「所选衣物」使用同一规则。比较包含颜色、属性、制作物及重复图层，而非只比较部件名称或滑块位置。手动调整部件后，下一步重新按当前内容判断；不会因为点击次数而回到补入。全局来源按钮直接处理全部部位，组级「置空」直接清空该组。

完全替换时，即使所选来源缺少该部件，滑块仍停留在该来源。只有明确选择置空，滑块才进入 `empty`，以区分「来源没有部件」和「用户主动清空」。

「保留原身形」将身体、面容及整个头发部位切回原角色，其他选择保留；「只替换身形」将这些部位切到所选衣物，其余切回原角色。发型与发色一起保留或替换。两个按钮都只修改本次预览。

## 实现与验证

- `outfit-slot-rules.js` 提供内容比较、下一步操作及 bundle 选择规则；`getGroupSourceAction` 返回操作和完成状态，`progressGroupSource` 执行当前操作。
- 切换目标角色时，仍有效的分组策略按新角色与该次操作前的部位选择重新计算；逐部件手动调整保留。
- `body-slots.js` 使用已知身体部位以及 BC 原始 AssetGroup 元数据；通用 Appearance 显示组不会让未知衣物被误判为身体。
- 预览与保存的衣物数据相互隔离。应用使用已准备的预览结果，避免原角色或制作物在预览期间变化导致最终配色与所见不一致。
- 画布使用可见性订阅和 BC 动态图片就绪机制，详见 [预览渲染](PREVIEW_RENDERING.md)。列表视图不订阅缩略图渲染。
- 单元测试检查分组状态推进、单部件选择、身形范围和目标切换；浏览器测试检查桌面右侧预览与微调弹窗、手机浏览与预览及微调的页面切换，以及显式应用。
