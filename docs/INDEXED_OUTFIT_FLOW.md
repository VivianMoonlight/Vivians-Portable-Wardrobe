# 索引衣柜与换装流程

当前发布分支为 `feat/wardrobe-react`，实现最初在 `design/react-ux-modernization` 上完成。运行 `npm run dev` 后访问 `/`，点击衣柜入口即可使用正式 React 组件。开发宿主为模拟环境，真实 BC 的资源、权限与扩展交互需要在游戏中确认。

## 找衣与预览

服装通过稳定 ID 建立索引，每件服装可引用多个全局唯一标签。旧文件夹按完整路径迁移为标签，迁移备份与云端冲突规则见 [索引与同步](INDEXED_WARDROBE_SYNC.md)。

浏览区用 CSS columns 展示不同高度的卡片，人物画幅保持 9:16。桌面侧栏列出全部、未标记、标签计数及云端/本地筛选；窄屏用抽屉。搜索覆盖服装和标签名称。

点击或键盘选择服装时，捕获目标角色当前外观作为原角色基准，全部部位先选择所选衣物，立即进入预览和微调。返回会保留浏览组件，因此搜索、筛选和滚动位置不丢失；再次选衣重新开始完整替换。衣柜卡片没有悬停换装、双击应用或菜单直接应用。

桌面预览与微调并排，手机上下排列。最终按钮显示「应用到角色名字」，固定在编辑页底部。只有这一操作会将本次衣柜预览应用到目标角色，游戏权限和锁定限制仍由 BC 适配器检查。

## 分组策略与部件来源

每个部件只记录 `original`、`incoming` 或 `empty`。单个滑块直接选来源，不参与点击循环。只有分组的两个来源按钮具有三阶段循环；组级置空直接清空该组。

以点击「所选衣物」分组按钮为例：

| 阶段 | 原角色和衣物均存在 | 仅原角色存在 | 仅衣物存在 |
| --- | --- | --- | --- |
| 第一次：补入 | 原角色 | 原角色 | 所选衣物 |
| 第二次：覆盖 | 所选衣物 | 原角色 | 所选衣物 |
| 第三次：完全替换 | 所选衣物 | 所选衣物来源，结果为空 | 所选衣物 |

第四次回到补入。「原角色」按钮按对称规则计算。每次都从两份来源重新计算，不在上次预览上累加，因此循环结果稳定。更换组来源或单独微调部件会清除该组点击阶段；全局来源按钮直接处理所有部位。

完全替换时，即使所选来源缺少该部件，滑块仍停留在所选来源。只有明确选择置空，滑块才进入 `empty`。这样能区分「来源没有部件」和「用户主动清空」。

「保留原身形」将身体、面容及整个头发部位切回原角色，其他选择保留；「只替换身形」将这些部位切到所选衣物，其余切回原角色。头发按完整滑块粒度处理，发型与发色一起保留或替换。两个按钮都是本次操作，不是持久偏好；旧默认替换行为设置已删除。

## 实现与检查

- `outfit-slot-rules.js` 提供纯粹的组策略和 bundle 选择规则；store 单独记录组点击阶段，避免把单部件状态与组策略混在一起。
- `body-slots.js` 使用已知身体部位以及 BC 原始 AssetGroup 元数据；未知衣物不会因被归到通用 Appearance 显示组而被误判为身体。
- 预览和保存的服装数据互相隔离。应用使用已准备的预览结果，避免角色或制作物在预览期间变化导致最终配色与所见不一致。
- 画布继续使用按可见性订阅和 BC 动态图片就绪机制，详见 [预览渲染](PREVIEW_RENDERING.md)。
- 单元测试覆盖三阶段双向策略、单槽来源、身形范围、账号切换、预览与应用隔离；浏览器测试覆盖桌面/手机完整流程、滚动返回、显式应用与渲染缓存。
